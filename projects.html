PDU Monitoring System

In Progress

Python-based monitoring daemon for a smart rack PDU. Polls outlet-level power draw via SNMP, stores time-series data, and pushes alerts when thresholds are exceeded. Integrates with Home Assistant for dashboard visibility.

Automated UPS load-shedding is now live: on battery, Home Assistant shuts down the desktop, then non-critical services, then each Proxmox node in order through its API. Per-outlet cost tracking is live too: a monthly report ranks every outlet by kWh and cost.

Inside the Homelab

The rack has grown well past a hobby box. Here's what's running on it.

Compute & Storage

Active

A four-node Proxmox cluster: a Tyan server with a Xeon Gold 5215 and 25GbE Mellanox networking, two Ryzen nodes, and an HP EliteDesk. TrueNAS runs as a VM with the SATA controllers passed straight through and serves NFS to the rest of the cluster.

Proxmox Backup Server runs weekly backups with retention, daily ZFS snapshots protect the main pool, and Scrutiny tracks SMART health on every drive.

Proxmox TrueNAS ZFS NFS PCIe Passthrough PBS

Networking & Secure Access

Active

A UniFi Dream Machine SE and USW-Pro-Max-24 run the network. Services are published through Cloudflare Tunnels with no open inbound ports, gated by Cloudflare Access and Authentik single sign-on across about 25 apps.

Tailscale handles private remote access, and a Windows Server 2025 VM runs a lab Active Directory domain.

UniFi Cloudflare Zero Trust Authentik Tailscale Active Directory

Monitoring & Logging

Active

Prometheus and Grafana dashboards for every node, including a custom exporter for the Intel Arc GPU. Graylog centralizes logs from Docker, Proxmox, TrueNAS, UniFi, Home Assistant, and the Windows domain controller.

Uptime Kuma watches every service, alerts land in Discord, and there's a public status page at status.klayshomelab.com.

Prometheus Grafana Graylog Uptime Kuma Discord

Command Center & Self-Healing

Active

A custom dashboard that tracks every service's installed version against the latest release, pending OS updates, media pipeline health, storage growth forecasts, and backup freshness, refreshed by systemd timers.

Behind it are self-healing jobs: timers that remount NFS when a cluster reboot races the NAS, a nightly fstrim across nodes, and the staged UPS shutdown.

Python systemd Bash REST APIs
